# Your first business feature: company profiles

The goal is to save a factory's name, address, and phone in PostgreSQL, then
retrieve the same details later, including after restarting the server.

## What was added

The `companies` table acts like an Excel sheet. Each saved company is a row.
Each row has its own UUID, which is a unique company ID.

| Column       | Meaning                                                       |
| ------------ | ------------------------------------------------------------- |
| `id`         | Unique company ID generated by the backend                    |
| `name`       | Required company name, up to 150 characters                   |
| `address`    | Optional address, up to 500 characters                        |
| `phone`      | Optional phone as text, up to 32 characters                   |
| `created_at` | When the record was created                                   |
| `updated_at` | When the record was last changed; initially the creation time |

Phone is text so leading zeroes and a `+` country prefix are preserved. Empty
optional fields become `null`. Company names do not have to be globally unique.

## Set up the table

From the project root, run:

```powershell
npm run db:migrate
```

A migration is a saved SQL file that describes a database change. The runner
records which files have already been applied. Running it again will skip those
files. Add a new migration for later changes; do not edit an applied migration.

## Save a company

Company APIs now require a signed-in account. For the full interface walkthrough,
see `FORGE-GUIDE.md`. To try the APIs manually, start the server with `npm run dev`.
After running the explicit development demo seed, sign in from a second
PowerShell terminal:

```powershell
$webSession = New-Object Microsoft.PowerShell.Commands.WebRequestSession
$loginBody = @{ email = "demo@madtech.local"; password = "ForgeDemo@2026!" } | ConvertTo-Json
$identity = Invoke-RestMethod -Method Post `
    -Uri "http://127.0.0.1:3030/api/auth/login" `
    -WebSession $webSession -ContentType "application/json" -Body $loginBody
$requestHeaders = @{ "X-CSRF-Token" = $identity.csrfToken }
```

Then create a company owned by your signed-in account:

```powershell
$companyDetails = @{
    name = "Green Bamboo Products"
    address = "Chennai, Tamil Nadu"
    phone = "+91 9876543210"
} | ConvertTo-Json

$companyResult = Invoke-RestMethod `
    -Method Post `
    -Uri "http://127.0.0.1:3030/api/companies" `
    -WebSession $webSession -Headers $requestHeaders `
    -ContentType "application/json" `
    -Body $companyDetails

$companyResult.data
```

This sends a POST request. POST means "create a record" here. A successful
response has HTTP status 201 and contains the saved company, including its ID.
Each successful POST creates a new company; replaying it creates another row.

## Read the saved company

In the same PowerShell terminal:

```powershell
$companyId = $companyResult.data.id
Invoke-RestMethod "http://127.0.0.1:3030/api/companies/$companyId" -WebSession $webSession
```

In a browser, sign into the same account first to access the URL. Stop and restart the server, then
request the same company ID. Its details remain because PostgreSQL stores them.
If you open a new PowerShell session, copy the saved ID rather than relying on
the previous session's `$companyResult` variable.

## How the files work together

```text
POST /api/companies
  -> company.routes.ts        Chooses the handler
  -> company.controller.ts    Passes the request to the service
  -> company.service.ts       Validates details and generates an ID
  -> company.validation.ts    Checks and trims the input
  -> company.repository.ts    Runs the INSERT query
  -> PostgreSQL               Stores the row
  -> controller               Sends the saved details back
```

| File                                           | Responsibility                                  |
| ---------------------------------------------- | ----------------------------------------------- |
| `database/migrations/001_create_companies.sql` | Defines the database table                      |
| `scripts/migrate.cjs`                          | Applies versioned database changes              |
| `src/app.ts`                                   | Connects `/api/companies` to the company routes |
| `company.routes.ts`                            | Defines POST and GET URLs                       |
| `company.controller.ts`                        | Receives requests and sends responses           |
| `company.service.ts`                           | Performs the create/read task                   |
| `company.validation.ts`                        | Rejects invalid data and IDs                    |
| `company.repository.ts`                        | Reads and writes PostgreSQL                     |
| `company.types.ts`                             | Describes company data for TypeScript           |

The company files live inside `src/modules/companies/`.
The SQL uses `$1`, `$2`, etc. to pass values separately from SQL commands.

## Responses

- `201`: company created.
- `200`: company found.
- `400`: invalid JSON, missing/invalid name, unsupported fields, invalid field
  types or lengths, or an invalid company ID. Validation errors identify fields.
- `404`: that company ID does not exist.
- `401`: sign in first, or the session has expired.
- `403`: a required CSRF token is missing or invalid.
- `500`: unexpected server/database failure; details are logged in the terminal.

Only `name`, `address`, and `phone` are accepted when creating a profile. The
backend creates the ID and timestamps.

## Verification

```powershell
npm run typecheck
npm run test:integration
```

The integration tests compile the app, apply migrations, create temporary
companies, and check create/read, validation, and persistence across a fresh
server process. They remove only the company IDs they created.

This is a local development API. Login and company membership checks now
protect company operations. Later production work includes a separate runtime
database role and database row-level security.
